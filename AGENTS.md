## Learned User Preferences

- Prefers the agent to run connectivity, installs, and setup steps directly in the terminal when asked, not only to describe commands to run manually.
- Wants the Claude Mem integration for Cursor maintained on a recurring upgrade schedule rather than set-and-forget.
- When instructions could apply to more than one machine, state clearly whether they target this Windows desktop or the remote home linuxbox.
- Prefers not to chain shell commands with `&&` when diagnosing problems; run commands separately so each failure is visible.
- Expects published memory tooling to favor an explicit **install path plus CLI scaffold** (for example `pip install` then `mem-constant init`) rather than relying on `git clone` alone to provision runtimes or integrations.
- Expects implementation tasks to be executed end-to-end (not left as plans), and treats an "implementation plan" as input to immediate implementation unless they explicitly ask to pause.
- For multi-phase migrations involving irreversible operations (folder renames, deletes, persona/reframe rewrites), expects an **explicit hard-pause checkpoint between phases**; reversible work can batch into a single phase, but each destructive step needs its own gated review with the user before it runs.
- Wants the Tailscale **exit node** on the **linuxbox only**; this Windows desktop should **not** be the tailnet exit endpoint unless explicitly requested.
- For **Hermes/OpenRouter** on linuxbox, credentials belong in **`~/.hermes/.env`** only—not **`~/.bashrc`** or **`~/.local/bin/env`** (the latter is PATH/shell setup).
